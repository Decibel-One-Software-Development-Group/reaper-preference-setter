## REAPER's save dialog opens on a name you chose

Saving a new project meant typing the name at the dialog every time, so a run
of shows came out named by whatever you managed at the moment of saving.

The Preferences tab now has a **New project name** row: a **prefix** for the
production and a **date** format to pick from. Type `MHET`, choose
`2026-09-17_1430`, and REAPER's Save New Project dialog opens on
`MHET_2026-09-17_1430`. The resolved name is shown as you set it, so it is
confirmed before you apply rather than at the next save.

This is REAPER's own feature — the save-as wildcard pattern, with REAPER's own
wildcards, and REAPER resolves them. The app composes the pattern and reads it
back, which means the setting lives in REAPER where it belongs and keeps
working whether or not you open this app again. A pattern you wrote by hand in
REAPER is read back intact rather than rewritten.

Five date formats, ISO first because it is the only one that sorts into date
order in Finder once a season has filled a folder. `(no date)` gives a plain
prefix. Leave both empty and REAPER's own default is left alone.

## Reports its real version

The 3.0.0 bundle told Finder it was version `0.0.0`, with `CFBundleVersion`
empty altogether. Pinning the version reached the app's own About box and
update check but not the bundle PyInstaller writes around it. Both keys are
stamped from the tag now, before signing.
